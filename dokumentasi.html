1 Ringkasan Aplikasi

Aplikasi internal untuk mengelola harga jual produk di berbagai marketplace/kanal penjualan, memantau harga kompetitor sebagai referensi, mencatat riwayat setiap perubahan harga, dan mengirim notifikasi email otomatis ke tim terkait setiap kali harga berubah.

📦 Master Produk

Kelola daftar produk, brand, dan biaya per vendor (modal, target HPP, SRP).

🏷️ Master Kategori Barang BARU

Kelompokkan produk berdasarkan kategori (mis. Minuman, Elektronik) untuk memudahkan pencarian & filter.

🚚 Master Vendor BARU

Kelola daftar vendor/pemasok beserta kontak, dipakai saat mengisi biaya produk dan Update Harga.

🏬 Master Kompetitor BARU

Kelola daftar kompetitor yang harganya dipantau sebagai referensi saat menentukan harga jual.

💰 Master Biaya BARU

Kelola daftar komponen biaya (nama + nominal Rupiah) yang bisa dikaitkan ke satu atau lebih Sales Channel.

🛒 Sales Channel BARU

Kelola daftar kanal penjualan (Offline, Website, Tokopedia, Shopee, dsb) beserta urutan tampil dan biaya tambahan dari Master Biaya.

💱 Update Harga

Form input Modal/HPP dan harga per kanal, dengan kalkulasi SRP, Markup%, dan Margin% otomatis.

📈 Harga Kompetitor

Catat harga kompetitor per produk sebagai pembanding sebelum menetapkan harga jual.

🕒 Riwayat Perubahan

Snapshot lengkap nilai lama vs baru setiap kali harga diubah, beserta status pengiriman notifikasi.

📧 Notifikasi Email

Email otomatis ke grup penerima yang berlangganan kanal tertentu setiap ada perubahan harga.

👥 User & Role

Manajemen akun dan hak akses berbasis role: Administrator, Editor, Viewer.

2 Arsitektur Teknis

Dibangun di atas CodeIgniter 3 (pola MVC klasik), dengan tampilan menggunakan Tabler — template admin open-source (MIT License, gratis) yang dibangun di atas Bootstrap 5 — plus Bootstrap Icons dan font Inter (semua dimuat via CDN, tanpa proses build tambahan). Data disimpan pada MySQL 8 / MariaDB.

3 Instalasi & Konfigurasi

  1. Install dependency PHP: 
    composer install
  2. Buat database lalu import struktur, kemudian data referensi: 
    -- 1) struktur tabel
SOURCE database_schema.sql;
-- 2) data contoh (role, marketplace, kompetitor, produk, admin)
SOURCE seed_sample_data.sql;
    ⚠️ Tabel roles, price_channels (Sales Channel), dan competitors wajib berisi data sebelum login/penggunaan modul harga bisa berjalan normal. Jika tidak memakai seed_sample_data.sql, isi ketiga master ini secara manual — Sales Channel & Kompetitor kini bisa diisi langsung lewat menu Master Data di aplikasi.
  3. Sesuaikan koneksi database di application/config/database.php dan pengaturan SMTP di application/config/email.php.
  4. Set base_url pada application/config/config.php (mis. http://localhost/price_update/).
  5. Arahkan document root web server ke folder proyek ini, pastikan modul mod_rewrite aktif (berkas .htaccess sudah disediakan).
  6. Login pertama kali menggunakan akun admin dari seed_sample_data.sql, lalu segera ganti password lewat menu Manajemen User.

6 Panduan Modul

6.1 Master Produk

Menu Master Data → Produk. Kelola kode produk, nama, brand, dan satuan. Tombol nonaktifkan menyembunyikan produk dari daftar aktif tanpa menghapus riwayat harga terkait.

6.2 Master Kategori Barang BARU

Menu Master Data → Kategori Barang. Halaman CRUD untuk tabel product_categories, dipakai untuk mengelompokkan produk. Daftar menampilkan kolom No (nomor urut tampilan, mengikuti halaman — bukan ID database), Nama Kategori, dan Status.

  • Tambah Kategori: isi Nama Kategori saja (mis. Minuman Keras, Elektronik). Nama harus unik.
  • Cari: kotak pencarian di atas tabel menyaring berdasarkan nama.
  • Edit: ubah nama dan status aktif (checkbox "Aktif" — cara menyembunyikan kategori dari pilihan baru tanpa menghapusnya).
  • Hapus BARU: tombol Hapus kini menghapus baris permanen dari tabel (sebelumnya hanya menonaktifkan). Jika kategori masih dipakai oleh satu atau lebih data Produk (products.category_id), penghapusan ditolak dan muncul notifikasi merah "Kategori "…" tidak bisa dihapus karena masih dipakai pada data produk." — lepaskan/kosongkan kategori dari produk terkait dulu bila memang perlu dihapus.
✅ Kategori bersifat opsional pada Produk — field ini tersedia sebagai dropdown Select2 "Kategori Barang" di form Tambah/Edit Produk (menu Master Data → Produk), lengkap dengan filter kategori pada daftar produk.

6.3 Master Vendor BARU

Menu Master Data → Vendor. Halaman CRUD penuh untuk tabel vendors. Kolom Kode Vendor tidak lagi diminta/ditampilkan di form maupun daftar — sistem membuatnya otomatis dari Nama Vendor (huruf besar, spasi/simbol jadi _, ditambah angka urut jika terjadi duplikat) dan tetap dipakai secara internal sebagai identitas unik. Daftar menampilkan kolom No (nomor urut tampilan), Nama Vendor, Kategori, dan Status.

  • Tambah Vendor: isi Nama dan Kategori (opsional — mis. Supplier CK, Supplier NCK, Umum).
  • Cari: kotak pencarian di atas tabel menyaring berdasarkan nama.
  • Edit: ubah nama, kategori, dan status aktif.
  • Hapus BARU: menghapus permanen. Ditolak dengan notifikasi jika vendor masih dipakai pada data product_vendor_costs (Cost per Vendor di modul Produk), product_prices (harga aktif di Update Harga), atau price_change_batches (riwayat perubahan harga).
✅ Vendor yang aktif otomatis muncul sebagai pilihan tab vendor baru di modul Produk (Cost per Vendor) dan Update Harga.

6.4 Master Kompetitor BARU

Menu Master Data → Kompetitor. Halaman CRUD penuh untuk tabel competitors. Kolom Kode dibuat otomatis dari Nama Kompetitor dan tidak ditampilkan di form/daftar. Daftar menampilkan kolom No (nomor urut tampilan), Nama Kompetitor, Website, dan Status.

  • Tambah Kompetitor: isi Nama dan Website (opsional).
  • Cari: kotak pencarian di atas tabel menyaring berdasarkan nama.
  • Edit: ubah nama, website, dan status aktif.
  • Hapus BARU: menghapus permanen. Ditolak dengan notifikasi jika kompetitor masih memiliki data harga tercatat di modul Harga Kompetitor (competitor_prices).
✅ Kompetitor yang aktif otomatis muncul sebagai kolom input di modul Harga Kompetitor dan sebagai referensi harga di modul Update Harga.

6.5 Master Biaya BARU

Menu Master Data → Master Biaya. Halaman CRUD penuh untuk tabel baru costs — daftar komponen biaya (mis. Biaya Admin, Biaya Komisi Marketplace, Biaya Packing) yang nantinya dikaitkan ke satu atau lebih Sales Channel (§6.6) sebagai biaya tambahan per kanal. Daftar menampilkan kolom No, Nama Biaya, Amount (nominal Rupiah tetap), dan Status.

  • Tambah Biaya: isi Nama Biaya (harus unik) dan Amount dalam Rupiah (mis. 5000 untuk Rp 5.000).
  • Cari: kotak pencarian di atas tabel menyaring berdasarkan nama.
  • Edit: ubah nama, amount, dan status aktif.
  • Hapus: menghapus permanen. Ditolak dengan notifikasi jika biaya tsb masih dikaitkan ke satu atau lebih Sales Channel (tabel relasi price_channel_costs) — lepaskan kaitannya dulu lewat Edit Sales Channel yang bersangkutan.
✅ Biaya yang aktif otomatis muncul sebagai pilihan multi-select "Biaya Tambahan" di form Tambah/Edit Sales Channel (§6.6). Satu sales channel bisa memakai lebih dari satu biaya sekaligus; satu biaya juga bisa dipakai ulang di banyak sales channel (relasi many-to-many lewat price_channel_costs).
ℹ️ Saat ini Master Biaya & relasinya ke Sales Channel bersifat data referensi (belum otomatis mengurangi/menambah perhitungan Markup%/Margin% di modul Update Harga) — integrasi ke kalkulasi harga akan menyusul.

6.6 Sales Channel BARU

Menu Master Data → Sales Channel (sebelumnya bernama "Master Marketplace"). Halaman CRUD penuh untuk tabel price_channels (kanal penjualan). Kolom Kode dibuat otomatis dari Nama dan tidak ditampilkan di form/daftar. Daftar menampilkan kolom No (nomor urut tampilan), Nama Sales Channel, Urutan (persis di sebelah kolom Nama), Biaya Tambahan BARU (daftar nama+nominal biaya dari §6.5 yang dikaitkan ke kanal ini, atau "-" jika tidak ada), dan Status.

  • Tambah Sales Channel: isi Nama tampilan, Urutan Tampil (angka kecil tampil lebih dulu di form Update Harga), dan Biaya Tambahan BARU (opsional, dropdown pencarian Select2 multi-pilih — bisa memilih lebih dari satu item dari Master Biaya).
  • Edit: ubah nama, urutan, biaya tambahan yang dikaitkan, dan status aktif.
  • Hapus BARU: menghapus permanen. Ditolak dengan notifikasi jika sales channel masih dipakai pada data harga aktif (product_prices). Kanal berkode OFFLINE tidak bisa dihapus sama sekali (ditolak otomatis apa pun kondisinya) karena menjadi acuan wajib perhitungan Markup%/Margin% — nonaktifkan lewat Edit jika benar-benar diperlukan.
⚠️ Jangan menonaktifkan sales channel bernama Offline kecuali Anda tahu konsekuensinya — kanal ini menjadi acuan perhitungan Markup%/Margin% di seluruh modul Update Harga.

6.7 Update Harga

Menu Draft Pricing → Update Harga. Daftar produk kini memakai paging (25 produk/halaman) plus pencarian kode/nama, sama seperti menu Produk. Pilih produk, lalu isi Modal & Margin per vendor — SRP Suggest, Markup%, dan Margin% (aktual) terhitung otomatis (real-time via AJAX). Isi harga jual baru untuk tiap sales channel aktif, bandingkan dengan harga kompetitor yang tampil sebagai referensi, lalu klik Simpan Perubahan Harga.

✅ Field "Target HPP" diganti "Margin" BARU. Input Modal & HPP kini bernama Modal & Margin: field Margin (%) (dulu "Target HPP") diisi target margin yang diinginkan dari harga jual, lalu SRP Suggest & Markup% dihitung otomatis memakai rumus SRP Suggest = Modal ÷ (1 − Margin% / 100) (mis. Modal Rp 652.500, Margin 30% → SRP Suggest Rp 932.143) — kebalikan dari rumus lama (Modal ÷ Target HPP%). Kotak hasil Margin % tetap dihitung dari harga jual aktual kanal Offline terhadap Modal (bisa berbeda dari angka Margin yang diketik, karena mencerminkan harga jual sesungguhnya, bukan target). Dropdown Tambah Vendor kini hanya menampilkan Nama Vendor (sebelumnya "Kode - Nama"). Layout formulir dirombak: kartu Modal & Margin kini tampil satu kolom penuh di atas, dengan kartu Harga Baru per Kanal (grid 3 kolom) di bawahnya — sebelumnya berdampingan. Kolom product_vendor_costs.target_hpp_pct di database tidak berganti nama (menghindari migrasi & menjaga kompatibilitas format import Excel yang masih memakai header target_hpp_pct, lihat §6.11) — hanya isinya yang kini merepresentasikan Margin% target, bukan Target HPP% lagi. Tabel "Cost per Vendor" di menu Produk turut disesuaikan labelnya jadi Margin (Target) & Margin (Aktual) agar tidak ambigu dengan dua kolom "Margin". Urutan tampil sales channel Harga Grosir (BtB) dipindah ke tepat di bawah Online (diatur lewat kolom Urutan di menu Sales Channel).
✅ Notifikasi digabung, bukan langsung terkirim per produk BARU. Menyimpan harga tidak lagi langsung mengirim email — batch tersimpan berstatus "Pending". Selama masih ada batch berstatus Pending di database (dihitung ulang setiap halaman dimuat, bukan disimpan di sesi login), muncul kotak kuning di bagian atas setiap halaman aplikasi — untuk siapa pun yang login sebagai ADMIN/EDITOR, bukan cuma yang membuat perubahannya: "N perubahan harga menunggu dikirim notifikasi" dengan tombol Kirim Notifikasi Sekarang, yang mengirim satu email per penerima merangkum semua produk Pending yang ada (misal update 10 produk berurutan → 1 email berisi 10 produk per penerima, bukan 10 email terpisah).

Setiap penyimpanan tetap tercatat sebagai batch riwayat (status awal "Pending"); isi email tiap penerima otomatis disaring hanya menampilkan marketplace yang benar-benar mereka langgani di menu Grup Notifikasi — sama seperti sebelumnya, hanya cara pengirimannya yang kini digabung. Karena sumber datanya database (bukan sesi), jumlah "menunggu" tetap akurat walau Anda logout lalu login lagi, atau login sebagai user lain.

🛠️ Perbaikan bug — kalkulasi otomatis & Preview Email sempat tidak berfungsi. Saat template diganti ke Tabler, skrip halaman ini memanggil new bootstrap.Modal(...) untuk tombol Preview Email — padahal JS bundel Tabler tidak menyediakan objek global bootstrap, sehingga baris itu gagal (ReferenceError) dan MEMATIKAN seluruh skrip di baliknya, termasuk listener kalkulasi otomatis SRP Suggest/Markup %/Margin % (jadi field Modal/Target HPP terlihat tidak menghitung apa-apa) dan tombol Preview Email (klik tidak bereaksi). Sudah diperbaiki dengan mengganti pemicu modal ke atribut data-bs-toggle bawaan Tabler — sudah diverifikasi langsung lewat browser otomatis (bukan cuma baca kode): kalkulasi live update dengan benar, modal Preview Email terbuka/tertutup normal, dan tidak ada error di console.
✅ Dropdown Tambah Vendor kini Select2 BARU. Sama seperti pola pencarian di Harga Kompetitor — mempermudah memilih vendor dari daftar 100+ vendor master. Kolom "Harga Baru per Kanal" sendiri memang sudah mengambil data dari Master Data → Sales Channel sejak awal (dikonfirmasi ulang saat perbaikan ini) — daftar kanal yang tampil otomatis mengikuti sales channel aktif di master, termasuk urutan tampilnya.

6.8 Harga Kompetitor

Menu Draft Pricing → Harga Kompetitor. Kini bergaya menu master (sama seperti Master Kompetitor/Vendor): daftar berpaging (25 baris/halaman) dengan pencarian, tombol Tambah Harga Kompetitor, dan form tambah/edit satu entri per submit — menggantikan form matriks lama (satu produk × semua kompetitor sekaligus).

  • Tambah: cari Produk lewat dropdown pencarian Select2 (mengetik minimal 2 huruf memicu pencarian AJAX ke katalog — dipakai karena jumlah produk terlalu besar untuk dropdown biasa), pilih Kompetitor dari dropdown yang datanya selalu diambil langsung dari Master Data → Kompetitor (hanya yang berstatus aktif), isi Harga dan Tanggal Pantau.
  • Jika kombinasi Produk + Kompetitor + Tanggal Pantau yang sama sudah pernah dicatat, sistem otomatis memperbarui harga tersebut alih-alih membuat duplikat.
  • Edit: Produk bersifat tetap (tidak bisa diganti), tapi Kompetitor, Harga, dan Tanggal Pantau bisa diubah.
  • Hapus: data harga kompetitor bisa dihapus permanen (bukan nonaktifkan) — catatan ini bersifat log observasi, bukan master data.

Data ini menjadi referensi visual saat menentukan harga jual di modul Update Harga.

6.9 Riwayat Perubahan

Menu Draft Pricing → Riwayat Perubahan. Menampilkan seluruh batch perubahan harga beserta status pengiriman notifikasi (Terkirim/Sebagian/Gagal), dengan detail nilai lama vs baru per marketplace.

  • Filter Produk kini Select2 BARU — dropdown pencarian (ketik minimal 2 huruf) menggantikan <select> berisi seluruh katalog produk.
  • Paging diperbaiki BARU — sebelumnya daftar nomor halaman polos tanpa navigasi Prev/Next dan kehilangan filter aktif saat pindah halaman. Sekarang 25 baris/halaman dengan navigasi First/Prev/Next/Last, kotak lompat ke halaman, dan seluruh filter (Produk, Status, rentang tanggal) tetap terjaga saat berpindah halaman.
  • Tombol "Export Excel" — terbuka untuk semua role BARU — mengunduh riwayat yang sedang tampil (mengikuti filter aktif) sebagai file .xlsx lewat price-history/export. Tersedia untuk ADMIN, EDITOR, maupun VIEWER yang bisa membuka halaman ini. Termasuk kolom Marketplace, Harga Lama, dan Harga Baru — karena satu batch bisa mengubah harga di beberapa marketplace sekaligus, setiap marketplace yang benar-benar berubah diekspor sebagai baris tersendiri (bukan digabung dalam satu sel) supaya angkanya tetap murni angka (bisa dijumlah/diurutkan di Excel). Marketplace yang harganya tidak berubah pada batch tsb tidak ikut dibuat baris. Batch tanpa perubahan harga marketplace (mis. hanya ubah Modal) tetap muncul satu baris dengan kolom Marketplace bertanda "-".
  • Tombol "Detail" — hanya aktif untuk ADMIN & EDITOR BARU — halaman detail menampilkan aksi "Kirim Ulang Notifikasi", jadi sengaja dibatasi. Untuk role VIEWER, tombol Detail tetap tampil di daftar tapi berupa tombol nonaktif (abu-abu, tidak bisa diklik) — bukan disembunyikan, supaya VIEWER tahu fitur ini ada tapi bukan untuk perannya. Percobaan membuka URL detail secara langsung oleh VIEWER tetap diblokir (403), bukan cuma disamarkan di tampilan.

Pembatasan tombol Detail ini bersifat tetap (hardcode di controller), berbeda dengan menu-menu lain yang aksesnya bisa diatur lewat Administrasi → Hak Akses — lihat §6.12.

6.10 Manajemen User & Grup Notifikasi

Khusus role ADMIN. Kelola akun pengguna beserta role-nya, dan kelola grup notifikasi (siapa menerima email untuk marketplace apa saja).

6.11 Import / Export

Menu Administrasi → Import/Export untuk memasukkan data produk/harga secara massal dan mengekspor laporan.

6.12 Hak Akses BARU

Menu Administrasi → Hak Akses, khusus role ADMIN. Matriks centang untuk menentukan menu apa saja yang bisa diakses role EDITOR dan VIEWER, dikelompokkan sama seperti sidebar (Master Data / Draft Pricing / Administrasi).

  • Centang sebuah kotak untuk mengizinkan role tsb membuka menu terkait; kosongkan untuk melarang.
  • Klik Simpan Hak Akses untuk menerapkan seluruh perubahan sekaligus (satu form menyimpan kolom EDITOR & VIEWER bersamaan).
  • Menu yang tidak dicentang untuk suatu role otomatis hilang dari sidebar role tsb — sesuai permintaan awal fitur ini: "kalau user tidak punya akses, menu di navbar jangan diaktifkan".
  • Perubahan berlaku seketika untuk user yang sedang login — tidak perlu logout/login ulang untuk melihat efeknya.
  • Percobaan membuka URL menu yang tidak diizinkan langsung (tanpa lewat sidebar) akan menampilkan halaman 403 Akses Ditolak, bukan cuma disembunyikan dari tampilan — jadi benar-benar diblokir, bukan sekadar disamarkan.
⚠️ Role ADMIN tidak muncul di matriks ini dan selalu punya akses penuh ke seluruh menu, termasuk halaman Hak Akses itu sendiri — supaya ADMIN tidak bisa mengunci dirinya sendiri lewat kesalahan konfigurasi.

7 Tampilan Desktop & Mobile

Seluruh halaman aplikasi — termasuk dua modul master baru — memakai layout responsif yang sama:

 Tampilan Desktop
☰ Mobile
  • Desktop (≥ 992px): sidebar navigasi selalu tampil di kiri, dikelompokkan per bagian (Master Data, Draft Pricing, Administrasi).
  • Tablet & Handphone (< 992px): sidebar tersembunyi secara default dan dibuka lewat tombol menu (☰) di pojok kiri atas; area konten otomatis melebar penuh, dan tabel data bisa digeser (scroll) horizontal bila kolom terlalu banyak.
  • Menu sidebar bisa di-scroll: jika daftar menu lebih panjang dari tinggi layar (mis. di layar pendek/handphone landscape), sidebar akan menampilkan scrollbar vertikal internal sehingga menu paling bawah (Import/Export, Keluar) tetap bisa dijangkau tanpa menggeser seluruh halaman.
  • Form, kartu statistik, dan tabel pada seluruh modul (termasuk Master Kategori Barang, Master Vendor, Master Kompetitor & Sales Channel) menyesuaikan lebar layar secara otomatis mengikuti grid Bootstrap 5.
Tidak perlu instalasi aplikasi terpisah — cukup buka alamat aplikasi dari browser HP (Chrome/Safari) untuk pengalaman yang setara dengan versi desktop.

8 Notifikasi Email & Cron

Setelah harga disimpan, sistem mengirim email notifikasi secara sinkron ke seluruh anggota grup yang berlangganan marketplace yang berubah. Untuk volume perubahan tinggi, antrean email juga dapat diproses via CLI:

php index.php cli send_email_queue

Jadwalkan perintah ini lewat cron job / Task Scheduler sesuai kebutuhan volume notifikasi harian.
